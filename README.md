# خشت — پایلوت بستهٔ پرونده‌های ملکی

نسخهٔ نمایشی بر پایهٔ مخزن `Khesht_v2` است. سه مدل «سرمایه‌گذاری»، «بازسازی» و «اجاره» و مسیر پرونده از پذیرش تا گزارش مالی نمونه را نمایش می‌دهد. خانهٔ نیاوران یک سناریوی نمونهٔ خرید ملک قدیمی، بازسازی و فروش کوتاه‌مدت است.

این خروجی یک Worker با D1 است. داده‌های پروژه، اعداد و تصاویر ساخت نمونه‌اند. پرداخت، قیمت مصوب عرضه، انتشار عمومی، صدور توکن و انتقال مالکیت انجام نمی‌شود. تصاویر تولیدشده عکس مستند ملک نیستند. AVM فعلاً از رابط حذف شده است. گزارش نمونه کارشناسی رسمی محسوب نمی‌شود.

## اجرای ساده در VS Code

راهنمای گام‌به‌گام در [README_VSCODE_FA.md](README_VSCODE_FA.md) است. مسیر پیشنهادی: `npm ci` و سپس `npm run local`. حساب محلی، ساخت و مهاجرت پایگاه در همین مسیر آماده می‌شوند.

## اجرای محلی

به Node.js نسخهٔ 22.13 یا جدیدتر نیاز است. در پوشهٔ پروژه:

```bash
npm ci
npm run build
npm run db:local
npm run dev
```

سپس `http://127.0.0.1:5173` را باز کنید. ورود ChatGPT در میزبانی Sites فراهم می‌شود؛ برای حساب مستقل محلی، پیش از اجرا `npm run auth:setup` را طبق بخش ورود مستقل انجام دهید. `npm run db:local` مهاجرت‌های اعمال‌نشده را با ثبت سابقه اجرا می‌کند. آزمون چندکاربرهٔ محلی با `npm run test:backend` و در محیط مجزا انجام می‌شود. بررسی ساخت:

```bash
npm run typecheck
npm run test:backend
npm run build
```

`npm run build` Worker را در `dist/` می‌سازد و `npm start` آن را با Wrangler اجرا می‌کند.
پس از ساخت، `npm run test:built` مسیرهای API و رندر صفحه را روی همان Worker در محیط جداگانه آزمایش می‌کند.

## گردش کار و دسترسی اختصاصی پرونده

راهنمای مرحله‌به‌مرحله و شواهد آزمون در [WORKFLOW_ACCEPTANCE_FA.md](WORKFLOW_ACCEPTANCE_FA.md) است. عضویت هر پروژه مستقل است؛ فقط مدیر سامانه اعضا را تعیین می‌کند. گذر از مراحل به شواهد، نسخهٔ جاری و تأیید مستقل وابسته است. تغییر شواهد، تأییدهای وابسته را باطل می‌کند. APIهای `GET/PUT /api/project-control/members` و `GET/POST /api/project-control/artifacts` به این منظور اضافه شده‌اند.

## بک‌اند فعلی

بک‌اند برای «پرونده و کنترل» طراحی شده، نه عملیات مالی. سایت خصوصی از شناسهٔ ورود ChatGPT استفاده می‌کند و در محیط میزبان، مدیر آغازین با متغیر محرمانهٔ `KHESHT_BOOTSTRAP_ADMIN_USER_ID` تعیین می‌شود.

- `GET/POST /api/data-room/documents`: فهرست و بارگذاری فایل اتاق داده؛ فایل در R2 خصوصی و متادیتا، هش SHA-256، سطح دسترسی و وضعیت بازبینی در D1 است.
- `GET /api/data-room/documents/:id`: دریافت فایل، فقط بعد از کنترل هویت و نقش.
- `POST /api/data-room/documents/:id/review`: ثبت نتیجهٔ بازبینی انسانی و سابقهٔ آن.
- `GET/POST /api/data-room/documents/:id/extraction`: مشاهدهٔ متن خوانده‌شده و ثبت متن دستی یا OCR، جدا از فایل خام و با کنترل نقش.
- `GET/POST /api/sample-reports`: نگهداری و تولید پیش‌نویس گرافیکی با گزیدهٔ منابع خوانده‌شده، دامنهٔ مرور و وضعیت بازبینی. این نسخه مبتنی بر قواعد محصول است؛ تحلیل هوش مصنوعی و کارشناسی رسمی انجام نمی‌دهد.
- `GET/PUT /api/project-control/stages`: مسئول، وضعیت و علت تصمیم هر گیت پرونده؛ فعال‌کردن یک گام تازه، گام فعال دیگر را خودکار عبور نمی‌دهد.
- `GET/POST /api/wealth/scenarios`: ذخیره و بازخوانی سناریوی کاملاً آموزشیِ شخصی؛ هیچ سفارش، پرداخت یا تخصیصی ایجاد نمی‌شود.
- `GET/POST /api/control/roles`: مدیریت نقش‌های کاربرانی که قبلاً وارد سایت شده‌اند؛ فقط مدیر.
- `GET/POST /api/pilot/records`: یادداشت خصوصی دربارهٔ پرونده.
- `GET/POST /api/projects`: ثبت، ویرایش نسخه‌دار و بایگانی پروژه؛ نقش مجاز تیم پرونده. پروژه‌های جدید در فهرست، جزئیات، اتاق داده و مدیریت ثروت ظاهر می‌شوند.
- `GET/POST /api/analysis`: محاسبهٔ مالی سمت سرور با ورودی کاربر و ذخیرهٔ سناریوهای شخصی. شامل هزینهٔ خرید/ساخت، هزینه‌های دیگر، بدهی، بهره، اجاره، خالی‌ماندن، خروج، کارمزد و زمان؛ سه سناریوی قابل مقایسه.
- `GET/PUT /api/member`: پروفایل کمینه، اسناد قابل دسترسی و اعلان‌های شخصی. از طریق فرم پروفایل نمی‌توان نقش را تغییر داد.
- `GET/POST/PUT /api/support/tickets`: تیکت، پاسخ و اعلان؛ دادهٔ هر عضو جدا و مدیر پاسخ‌گو است.
- `GET /api/admin/operations`: کنترل سلامت D1/R2، نقش‌ها، رویدادها و سابقهٔ پشتیبان؛ فقط مدیر.
- `POST/GET/PUT /api/admin/backups`: ساخت نسخهٔ داده و کپی فایل خام، دریافت خروجی و کنترل هش؛ فقط مدیر. اجرای دستی در پنل و مسیر اشتراکی نگهداری روزانه موجود است؛ زمان‌بندی در سرویس میزبانی جداگانه ثبت می‌شود.

داشبورد و فهرست پرونده‌های مورد پیگیری از دادهٔ ذخیره‌شدهٔ حساب خوانده می‌شوند. درخواست اولیهٔ سازنده به تیکت قابل پیگیری تبدیل می‌شود. مسیر ورود قدیمیِ OTP از جریان فعال کنار گذاشته شده و ورود حساب با ChatGPT انجام می‌شود. KYC رسمی و سرویس پیامک هنوز متصل نیستند.

همهٔ نوشتن‌های API کنترل مبدأ و محدودیت درخواست دارند (۸۰ نوشتن در دقیقه برای هر کاربر؛ پشتیبان ۳ درخواست در دقیقه). سقف‌های فیلد و فایل در سرور نیز کنترل می‌شوند. نقش‌ها و دسترسی هر سند در سرور بررسی می‌شود. تغییر متن، بازبینی قبلی سند را به انتظار بازمی‌گرداند. محدودیت یکتای پایگاه داده از فعال‌شدن هم‌زمان دو مرحله جلوگیری می‌کند.

## OCR و نگهداری روزانه

`npm run dev` و `npm run build` پیش از اجرا موتور و مدل‌های OCR را از بسته‌های نصب‌شده به `public/ocr` کپی می‌کنند. هیچ سندی برای OCR به سرویس بیرونی فرستاده نمی‌شود. `npm run test:ocr` موتور واقعی را با مدل‌های فارسی و انگلیسی روی تصویر آزمایشی اجرا می‌کند؛ این آزمون جای آزمون مرورگر را نمی‌گیرد.

مسیر `GET/POST /api/internal/maintenance` فقط با مرز دسترسی Site مالک‌خصوصی و تنظیم صریح دو متغیر نگهداری فعال است. نتیجهٔ روزانه در D1 ثبت می‌شود؛ اجرای هم‌زمان قفل و اجرای تکراری از همان نتیجه استفاده می‌کند. جزئیات ایمنی، احراز سرویس، خواندن نتیجه و محدودیت‌ها در [OPERATIONS_FA.md](OPERATIONS_FA.md) آمده است. پیش از تغییر مخاطب سایت، این مسیر را غیرفعال کنید.

## آزمون و بازیابی

`npm run test:backend` پایگاه D1 و فضای R2 جداگانه می‌سازد و دادهٔ نسخهٔ اصلی را تغییر نمی‌دهد. ۱۳۳ بررسی شامل ثبت و ویرایش هم‌زمان، دسترسی نقش‌ها، بارگذاری/دریافت فایل، متن خوانده‌نشده، گزارش، محاسبهٔ مرجع مالی، تفکیک کاربران، پشتیبانی، اعلان‌ها، محدودیت درخواست و بازیابی پشتیبان در پایگاه خالی انجام می‌شود. `npm run test:built` پس از ساخت، ۴۳ بررسی دیگر را روی Worker واقعیِ تولیدشده انجام می‌دهد؛ شامل مسیرهای اصلی، رندر صفحات و اجرای کنترل مبدأ. این آزمون‌ها جای آزمون تعاملی مرورگر یا ممیزی مستقل امنیت را نمی‌گیرند.

پشتیبان شامل JSON داده و فهرست نسخه‌های کپی‌شدهٔ فایل‌های خام در R2 خصوصی است. پس از ساخت، هش داده و همهٔ فایل‌ها بررسی می‌شود. خروجی داده را از پنل مدیر بگیرید. هر فایل خام پشتیبان با `/api/admin/backups?id=<backup-id>&document=<document-id>` برای مدیر قابل دریافت است. خروجی SQL بازیابی را با دستور زیر بسازید:

```bash
node scripts/backup-sql.mjs khesht-backup.json restore.sql
```

این اسکریپت فقط INSERT تولید می‌کند و فایل موجود را بازنویسی نمی‌کند. SQL را فقط روی پایگاه خالیِ مجزا، پس از اعمال مهاجرت‌ها اجرا کنید؛ فایل‌های خام را از نسخه‌های کپی‌شده با کلیدهای `originalKey` بازگردانید. بازیابی خودکار روی پایگاه جاری و حذف داده در رابط فعال نیست. سقف پشتیبان تعاملی ۲۰٬۰۰۰ رکورد در هر جدول و ۲۵ مگابایت JSON است؛ برای حجم بالاتر خروجی مدیریت‌شده لازم است.

جداول D1 شامل پروفایل نقش، پرونده، گیت‌های تصمیم، اسناد اتاق داده، بازبینی اسناد، سناریوی ثروت و لاگ ممیزی هستند. در این پروژه جدول یا API برای پرداخت، سفارش، تخصیص، کیف پول، صدور توکن یا قیمت مصوب وجود ندارد. احراز هویت واقعیِ مستقل، KYC، پرداخت و عملیات حقوقی عمداً خارج از محدوده‌اند.

## مسیرها و محدوده

برای آزمون ورودی و خروجی، در پروندهٔ یک پروژه به اتاق داده بروید، PDF متن‌دار بارگذاری کنید، متن استخراج‌شده را مرور کنید و «ساخت گزارش آزمایشی» را بزنید. PDF اسکن‌شده و تصویر با OCR فارسی و انگلیسی روی دستگاه کاربر پردازش می‌شوند. متن OCR تا تطبیق و تأیید انسانی با حالت `needs_review` از منابع گزارش کنار گذاشته می‌شود. استخراج ناقص یا کم‌کیفیت، فایل را در حالت ناموفق نگه می‌دارد. سابقهٔ صفحه‌ها، اطمینان گزارش‌شدهٔ موتور و تأییدکننده جدا ذخیره می‌شود. حداکثر ۲۰ صفحهٔ اسکن‌شده در هر فایل پردازش می‌شود. سقف هر فایل ۱۵ مگابایت، هر PDF ۵۰۰ صفحه و متن هر سند ۱۲۰٬۰۰۰ نویسه است؛ متن بلند به‌صورت پنهانی بریده نمی‌شود.

دو جدول `document_extractions` و `sample_reports` متن و پیش‌نویس‌ها را نگهداری می‌کنند. فایل‌های پژوهشی پیوست گفت‌وگو خودکار وارد پایگاه عملیاتی یا به‌عنوان منابع اعمال‌شده معرفی نشده‌اند.

- `/`: معرفی پایلوت، پرونده‌های نمونه، سه مسیر محصول و گیت‌های کنترل
- `/projects`: فهرست پرونده‌ها؛ `/projects/shahrak-west`: جزئیات یک پرونده
- `/projects/shahrak-west/documents`: اتاق اسناد و تصاویر نمادین مراحل ساخت
- `/how-it-works`: نه مرحلهٔ پایلوت
- `/dashboard`: میزکار حساب با شمارش پرونده‌ها و تحلیل‌های ذخیره‌شده
- `/market`: علاقه‌مندی داده‌نما در D1؛ بدون سفارش یا تخصیص واقعی
- `/portfolio`: پرونده‌هایی که کاربر برایشان یادداشت یا تحلیل ذخیره کرده است
- `/finance`: محاسبهٔ مقدماتی سازنده و ثبت درخواست بررسی در پشتیبانی
- `/admin`: مدیریت پروژه، نقش، سلامت سرویس، رویداد و نسخهٔ پشتیبان

شرح نیازمندی‌ها و تصمیم‌های باز در [PRODUCT_SPEC_FA.md](PRODUCT_SPEC_FA.md) آمده است. رنگ‌ها و قواعد بصری در `app/visual-system.css` متمرکزند؛ نشان لوزی نیترو اورنج در `public/khesht-logo.svg` حفظ شده است.

## تکمیل پس از اسکن فنی

مشخصات جاری و ماتریس پذیرش در `PRODUCT_SPEC_FA.md` و دفتر منابع در `SOURCE_REVIEW_FA.md` قرار دارند. شمارهٔ نسخه تنها کنترل هم‌زمانی نیست: تصویر تغییرهای پرونده، متن، سند، عضویت، شواهد و تصمیم مرحله در تراکنش اصلی به تاریخچه افزوده می‌شود. سابقهٔ قبل از این مهاجرت بازسازی نشده است.

صف پرونده‌ها و قواعد اعلان اکنون از سرور خوانده می‌شوند. مدیریت ثروت و محاسبهٔ خلاصهٔ پروژه نرخ‌های کتابخانهٔ نمایشی را استفاده نمی‌کنند؛ منبع آن‌ها برنامهٔ مالی منتخب است. گزارش مالیِ تأییدشده برای عضو همان پروژه قابل مشاهده است. بازگشایی تأیید، دسترسی عضو را متوقف می‌کند و نسخه برای تیم با برچسب تاریخی باقی می‌ماند. `/api/project-control/report?project=<slug>` گزارش فارسی مستقل برای چاپ یا Save as PDF مرورگر است؛ فایل PDF در سرور تولید نمی‌کند.

### ورود مستقل برای اجرای محلی

```bash
npm ci
npm run auth:setup
npm run build
npm run db:local
npm run dev
```

سپس `/auth` را باز کنید. `auth:setup` به‌صورت تعاملی ایمیل و گذرواژهٔ حداقل ۱۶ نویسه را می‌گیرد و فقط هش آن را در فایل خصوصی و نادیده‌گرفته‌شدهٔ `.dev.vars` می‌نویسد. فایل موجود را بازنویسی نمی‌کند. پیکربندی `.dev.vars` را با source، ZIP یا Git منتشر نکنید. در میزبانی مستقل از HTTPS استفاده و همین مقادیر را به‌صورت secrets تنظیم کنید. نشست هشت‌ساعته با کوکی HttpOnly و SameSite=Strict و در HTTPS با Secure نگهداری می‌شود؛ شناسهٔ تصادفی نشست در پایگاه فقط به‌صورت هش ثبت می‌شود. ورود محدودیت ۱۰ تلاش در ۱۵ دقیقه برای هر ایمیل دارد. هش گذرواژه PBKDF2-SHA256 با نمک تصادفی و ۱۰۰٬۰۰۰ تکرار است؛ گذرواژهٔ بلند و یکتا ضروری است. حساب‌های دیگر در پنل مدیرِ حالت مستقل ساخته و سپس به پروژه منصوب می‌شوند. این مسیر KYC رسمی نیست.

حالت مستقل فقط با `KHESHT_AUTH_MODE=local-session` فعال می‌شود و هدرهای هویت Sites را نادیده می‌گیرد. در نسخهٔ میزبانی‌شدهٔ فعلی، ورود ChatGPT حفظ شده است. پیکربندی راه‌اندازی، ورود عمومی یا تغییر مخاطبان Site ایجاد نمی‌کند.

### آزمون‌های تکمیلی

```bash
npm run test:backend
npm run test:local-auth
npm run test:dependencies
npm run build
npm run test:built
npm run test:ocr
```

آزمون ورود مستقل از گذرواژه و کوکی واقعی در محیط جدا استفاده می‌کند؛ مسیر کامل تهیه‌کننده، بازبین و عضو را بدون تزریق هدر هویت طی می‌کند. این آزمون، تأیید انسانی ملک یا آزمایش حساب دوم در سایت اصلی نیست.

برخی وابستگی‌های ابزار ساخت به نسخه‌ای از `braces` متکی بودند که نسخهٔ اصلاح‌شدهٔ upstream برای آن منتشر نشده بود. یک fork محلی MIT با نام `@khesht/bounded-braces` حدود ورودی، عمق و توسعهٔ الگو را اعمال می‌کند. منشأ، مجوز و وصله در `vendor/bounded-braces/PATCH.md` ثبت و با `test:dependencies` آزموده می‌شود. اسکن صفر به‌تنهایی گواهی امنیت نیست و این fork باید همراه ارتقای بعدی ابزارها بازبینی شود.

## اصلاحات ۲۱ اکتبر: آمادگی بهره‌برداری و حساب مستقل

- `/admin` ← «آمادگی بهره‌برداری»: دفتر شواهد با تاریخچهٔ تغییرناپذیر برای آزمون مرورگر، دو نفر واقعی، پروندهٔ واقعی، امنیت، پشتیبان و سیاست داده.
- `/pilot-policy`: ضوابط عملکرد فعلی و تصمیم‌های باز؛ متن قرارداد یا سیاست مصوب نیست.
- حساب مستقل: تغییر گذرواژه از `/profile`، بازیابی با کد یک‌بارمصرف ۱۵دقیقه‌ای از `/auth/recovery` و ابزار مدیر برای لغو نشست، بازیابی و غیرفعال‌سازی. کد بازیابی را فقط پس از تطبیق هویت از مسیر امن به صاحب حساب تحویل دهید. کدها و گذرواژه در لاگ ثبت نمی‌شوند. مالک bootstrap از secrets سرور مدیریت می‌شود.
- پشتیبان کامل TAR از پنل سلامت قابل دریافت است؛ فایل خام نیز همراه داده‌هاست. این قابلیت، اتصال خودکار به مقصد مستقل نیست.
- نگهداری امضاشده با کنترل replay برای حالت اشتراکی آماده شده؛ فعال‌سازی به پیکربندی مستقل مطابق OPERATIONS_FA.md نیاز دارد.
- `npm run test:maintenance-auth` کنترل امضا و منع replay را در محیط مستقل بررسی می‌کند.
- فهرست دقیق کارهای انجام‌شده و موارد وابسته به اشخاص/دسترسی واقعی: [REMAINING_WORK_FA.md](REMAINING_WORK_FA.md).

آزمون مرورگری این نوبت محدود بود: منو و راهنما اجرا شدند؛ بارگذاری تصویر و OCR به تأخیر زیرساخت مرورگر و خطای زمان پاسخ برخوردند. ورود خصوصی و مسیر کامل کلیک‌ها تأیید نشده‌اند. صفحهٔ آزمایشی موقت از خروجی نهایی حذف شده است.
